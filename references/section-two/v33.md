# V33 — prevent third-section skips

Source baseline: V32, `147bececfa837be3f67e3220d50d2dc9d32c0b03`.

The V32 section controller released its transition lock before the fitting-room introduction finished. Wheel inertia could therefore navigate from the question straight into section four, and the same wheel gesture could continue from section four through section three into section two.

The wheel controller now consumes the tail of a gesture across page transitions and the fitting-room introduction. Navigation resumes only when the fitting room has `fitting-arrived` and wheel input has been quiet for 240 ms. Each subsequent deliberate gesture can navigate normally. Held navigation keys cannot cross multiple fitting-room boundaries, and a touch gesture remains bound to the screen where it began. The existing horizontal slide, visual styles, and clothing/panel scrolling are preserved.

Validation:
- Node syntax check; git diff whitespace check.
- Four regression tests execute the actual wheel handler: long entry inertia, long reverse inertia, horizontal inertia, clothing-rail exclusion.
- Native browser: click TRY AN EXAMPLE, continuously send 91 wheel scrolls over 9 seconds spanning the entire entrance. Result: `#next`, `fitting-arrived`, exactly one active screen.
- Fresh forward wheel gesture reaches `#fourth`; continuous reverse wheel input for 3.5 seconds returns to `#next` and stays there, with exactly one active screen and the model ready.
- Holding Down throughout the second-to-third entrance for 9 seconds stays on the fitting room. Holding Up during a fourth-to-third return stays on the fitting room.
